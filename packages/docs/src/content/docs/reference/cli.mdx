## Setup

| Command | | What it does |
|---|---|---|
| `sandboxr init` | D | One-time machine setup: DNS resolution for the domain suffix, a trusted certificate, and the shared router. Needs `sudo` once locally, and prints the command if it cannot elevate. |
| `sandboxr doctor` | D | Checks the setup and names what is missing rather than merely failing. Docker reachable, resolver answering, certificate present and unexpired, router running, password set, enough free disk. |
| `sandboxr base build` | D | Builds the **shared** base image: the supervisor, the router, the object store, `jq` and the container scripts. Generic, one per machine, and needed only when the base itself changes. |
| `sandboxr image build` | D | Builds the **per-project** layer on top of the base: the toolchains, the database engine and the dependency install. Needed after a `toolchain:`, `database:` or lockfile change. |

The two-image split is [a design decision](/architecture/decisions/), and getting the two
commands the wrong way round is the most likely way to spend twenty minutes rebuilding
something that did not change.

## Sandbox lifecycle

| Command | | What it does |
|---|---|---|
| `sandboxr up [slug]` | D | Starts a sandbox from the current worktree. Idempotent — re-run it to reconcile a running container with a changed config, or after a dependency change. |
| `sandboxr up --with <label>` | D | Also starts an app marked `optional: true`. |
| `sandboxr up --memory <size>` | D | Raises the per-sandbox memory limit for this run. |
| `sandboxr ensure <branch>` | D | Finds or creates a worktree for a branch, then brings a sandbox up. Never offers your main checkout. |
| `sandboxr restart [slug]` | D | Restarts the supervised processes. Does not touch the database or re-run migrations. |
| `sandboxr down <slug>` | D | Removes the container, its database volume, its storage volume, its built artefacts, and its hostnames. **Leaves the worktree and the logs.** |
| `sandboxr list` (`ls`) | C | Every sandbox on the machine. A pure function of `docker ps`. |
| `sandboxr gc [--merged] [--dry-run]` | C | Reaps sandboxes whose worktree no longer exists; `--merged` also those whose pull request is merged (needs `gh`). Also prunes Docker's build cache. |

## Rebuilding

| Command | | What it does |
|---|---|---|
| `sandboxr reload --backend [name]` | D | Rebuilds and restarts one backend, or all of them. ~2s. |
| `sandboxr reload --app <label>` | D | Rebuilds one front-end. ~3s, more for large sites. |
| `sandboxr reload --app all` | D | The project's main front-ends, excluding anything with `in_build_all: false`. |
| `sandboxr reload --app built` | D | Exactly what this sandbox has already built. Falls back to `all` if nothing is built. |

The `all` / `built` distinction is [explained here](/use/edit-and-reload/#all-and-built-are-not-the-same-thing-on-purpose).

## Inspecting

| Command | | What it does |
|---|---|---|
| `sandboxr logs <slug> [service] [-f]` | D | Tails logs. `db-init` is the service to read when a sandbox comes up `degraded`. Logs live on the host and survive `down`. |
| `sandboxr shell [slug]` | D | A shell inside the sandbox, in `/workspace`, with the project's toolchain on `PATH`. Edits here are edits to your branch. |
| `sandboxr dash [open\|restart]` | D | Opens or restarts the dashboard. |

## Databases

All of these work with no sandbox, no router and no DNS. A sandbox does the same thing at boot
against its own internal database.

| Command | | What it does |
|---|---|---|
| `sandboxr db fork` | D | Copies the source into a scratch database at the declared version, creates users and grants, heals stuck migration bookkeeping, takes the schema baseline. |
| `sandboxr db pending` | D | What this branch's migrations would run. Per-worktree, so two branches differ legitimately. |
| `sandboxr db migrate` | D | Runs the project's own migration command. Never reimplements it. |
| `sandboxr db diff` | D | Structure-only diff against the baseline. Works after a failure — the baseline is only re-taken after a success. |
| `sandboxr db snapshot` | C | The structure-only snapshot the driver interface defines. |
| `sandboxr db reset` | D | Back to a clean restore, baseline re-taken, fixtures re-applied. |
| `sandboxr db shell` | C | An interactive client against this sandbox's database. |
| `sandboxr db refresh [--force]` | D | Re-takes the cached seed artifact. `--force` ignores the content fingerprint. |

The walkthrough is [testing a migration](/databases/testing-a-migration/).

## Secrets

| Command | | What it does |
|---|---|---|
| `sandboxr secrets import` | D | Reads `secrets.read`, applies `keep`, `rename` and `never`, writes `~/.sandboxr/secrets/<project>.env`. Prints **names and counts only, never values.** |
| `sandboxr secrets list` | D | The names currently imported for this project. Again, names only. |

## Global options

| Option | What it does |
|---|---|
| `--project <name>` | Act on a project other than the one in the current directory. |
| `--dry-run` | Say what would happen. Supported wherever it is meaningful. |
| `--json` | Machine-readable output, for `list` in particular. |
| `-v`, `--verbose` | Verbose tracing. See also `SANDBOXR_DEBUG`. |

## The slug argument

Most commands take an optional slug and default to the current worktree's. The slug is derived,
in order of preference:

1. an explicit argument
2. a ticket-style id anywhere in the worktree directory name — `/[a-z]+-[0-9]+/i`
3. that same pattern in the branch name
4. the branch name
5. the worktree directory name

Then sanitised: lowercase, every character outside `[a-z0-9-]` becomes `-`, runs of `-`
collapse, leading and trailing `-` are stripped. **Ceiling 31 characters** — over that, the
first 22 characters plus `-` plus the first 8 characters of the SHA-256 of the *raw* input.

That derivation is contract, and the ceiling is
[load-bearing](/databases/mysql/#the-advisory-lock-and-why-slugs-are-hashed).

## What each command touches

| Command | Container | Database | Storage | Built apps | Worktree | Host state |
|---|---|---|---|---|---|---|
| `init` | – | – | – | – | – | **writes** |
| `up` | creates/reconciles | provisions | provisions | – | reads | writes env |
| `restart` | restarts | – | – | – | – | – |
| `reload` | – | – | – | **rebuilds** | reads | – |
| `db migrate` | – | **writes** | – | – | reads | – |
| `db reset` | – | **replaces** | – | – | reads | – |
| `db fork` | – | writes scratch | – | – | reads | writes cache |
| `down` | **removes** | **removes** | **removes** | **removes** | – | – |
| `gc` | **removes** | **removes** | **removes** | **removes** | – | prunes cache |
| `secrets import` | – | – | – | – | reads | **writes** |

No command writes to the source database. That is the whole
[driver contract](/databases/drivers/#1-the-source-database-is-only-ever-read).
