A lookup table. The narrative walkthrough with reasoning is
[sandboxr.yaml, field by field](/config/sandboxr-yaml/).

The authoritative schema is `packages/core/src/config/schema.ts` (Zod). Where this page and the
schema disagree, the schema wins.

<Aside type="caution" title="This page follows the example configs, not §5's snippet">
`contracts.md` §5 sketches the file but its YAML **does not parse**: it shows a `defaults:`
mapping key as a sibling of block-sequence items under `backends:`. The example configs use
`backends: { defaults, services }` and `frontends: { root, defaults, apps }`, and that is what
is documented here.

Fields marked **(ex)** appear only in the examples, not in §5's snippet. Fields marked
**(5.4)** are specified in §5.4, which was added after the original snippet. Recorded on
[what is built](/reference/status/).
</Aside>

|---|---|---|---|---|
| `project` | string, `[a-z0-9-]` | **yes** | – | Appears in hostnames, container names and volume names. |
| `sandboxr` | semver range | no | – | Minimum tool version. A mismatch is a clear error at parse time. |
| `database` | object | no | driver `none` | |
| `backends` | object | no | – | |
| `frontends` | object | no | – | |
| `routes` | object | no | – | |
| `secrets` | object | no | – | |
| `storage` **(5.4)** | object | no | driver `none` | |
| `toolchain` | object | no | – | |
| `access` | object | no | see below | |

## `database`

| Field | Type | Required | Notes |
|---|---|---|---|
| `driver` | `mysql` \| `d1` \| `sqlite` \| `none` | **yes** if `database` present | Selects the whole implementation. |
| `version` | string | driver-specific | For `mysql`, the server version to restore **into** — the one production runs, not the developer's. |
| `owner` **(5.4)** | string (app or service name) | **yes** for `d1`/`sqlite` | The single service allowed to open the file. Two writers deadlock. |
| `seed_from` | object | no | Omit for a project whose migrations build the schema from nothing. |
| `migrate` | object | no | |

### `database.seed_from`

| Field | Type | Notes |
|---|---|---|
| `local.container` | string | A database container on this machine to fork. **Read only, always.** |
| `local.database` | string | The database inside that container. |
| `file` | path | A dump to restore, or a state directory for a file-based driver. |
| `fixtures` | path | SQL applied **after** migrations. A failure is reported and non-fatal. |

<Aside type="caution" title="Precedence between `local` and `file` is unspecified">
Both may be set and nothing says which wins. The examples imply `local` on a laptop and `file`
on a server. Set only the one you mean.
</Aside>

For a `public` project, `local` is refused — a public URL over a fork of live data is a data
leak. [The rules](/security/public-sandboxes/).

### `database.migrate`

| Field | Type | Notes |
|---|---|---|
| `command` | string | The project's own migration command. sandboxr shells out to it and never reimplements it. |
| `workdir` | path | Where to run it, relative to the repo root. |
| `since` | string | Exported to the command as `SANDBOXR_MIGRATE_SINCE`. **The command must reference it** — it is not a flag sandboxr adds. |
| `failure_pattern` | regex | Treat output matching this as a failure even when the runner exits zero. |
| `file_pattern` | regex | How to extract the failing migration's filename from the output. |
| `error_pattern` | regex | How to extract the error text from the output. |

## `backends`

| Field | Type | Where | Notes |
|---|---|---|---|
| `defaults` | object | – | Inherited by every entry in `services`. |
| `services` | array | – | The backends. |
| `name` | string | per service | Directory name and identity in `logs`, `reload` and `routes`. |
| `port` | number | per service | Internal only — nothing is published to the host. Unique within the sandbox. |
| `label` | string | per service | Hostname component. Omit for a service with no hostname of its own. |
| `build` | string | defaults or per service | `{name}` and `{out}` are substituted. |
| `workdir` **(ex)** | path | defaults or per service | Relative to the repo root. |
| `health` **(ex)** | path | defaults or per service | Returns 200 when ready. |

## `frontends`

| Field | Type | Where | Notes |
|---|---|---|---|
| `root` **(ex)** | path | – | Prefix for every `package`. |
| `defaults` **(ex)** | object | – | Inherited by every entry in `apps`. |
| `apps` | array | – | The front-ends. |
| `label` | string | per app | Hostname component, and the name `reload --app` takes. |
| `package` | path | per app | Relative to `root`. `.` means the repo root. |
| `build` | string | defaults or per app | Runs in the package directory. |
| `out` | path | defaults or per app | Where the build lands. **Its presence makes the app `static`.** |
| `static_mode` **(5.4)** | `spa` \| `html` \| `files` | per app | Default `spa`. How the built directory is served. The wrong value half-works rather than failing. |
| `serve` | string | per app | A long-running command. **Its presence makes the app `server`.** |
| `prepare` | string | per app | A one-off command run before a `serve:` process starts. |
| `port` **(ex)** | number | per app | Required with `serve`. |
| `memory` **(ex)** | size, e.g. `6g` | per app | Build memory ceiling. |
| `optional` **(ex)** | boolean | per app | `true` means it starts only with `up --with <label>`. |
| `in_build_all` **(5.4)** | boolean | per app | Default `true`. `false` excludes it from `reload --app all`. |

`out` and `serve` are mutually exclusive; they are what pick between two of
[the three runtime kinds](/config/runtime-kinds/).

## `routes`

```yaml
routes:
  <app-label>:
    "<path-prefix>": <service-name>
```

Keys are app `label`s. Each entry maps a path prefix on that hostname to a backend or a `serve:`
front-end. Matched **most-specific-first** — declare `"/api/admin"` before `"/api"` or `/api`
swallows it.

## `secrets`

| Field | Type | Notes |
|---|---|---|
| `read` | array of paths | Files to read variables from, relative to the repo root. |
| `keep` | array of names | Allowlist. Anything not listed is dropped. |
| `rename` | map, `from: to` | Import under a different name. Load-bearing — see [why](/config/secrets/#why-rename-exists). |
| `never` | array of glob patterns | Denylist, applied last. Anything describing *where* something runs belongs here. |

Values are never printed or logged. The import reports a count and a list of names.

## `storage` **(5.4)**

| Field | Type | Notes |
|---|---|---|
| `driver` | `minio` \| `none` | Default `none`. Object storage inside the sandbox. |
| `buckets` | array of names | Created at first boot. |

Specified in §5.4; §3.3 reserves a `blob` volume for it.

## `toolchain`

| Field | Type | Notes |
|---|---|---|
| `go` | version string | Installed in the per-project image layer. |
| `node` | version string | Same. |

The toolchains live in a thin per-project layer on top of a small shared base, so adding a
project costs one layer rather than another base image.

Changing either rebuilds **the project layer** (`sandboxr image build`), not the shared base.
`sandboxr base build` is only needed when the base itself changes — the supervisor, the
router, the object store or the container scripts.

Go and Node are resolved from their vendors' release indexes, so a prefix such as `"24"` picks
the latest matching release at build time. MySQL cannot be: its download host publishes no
machine-readable release list, so a series such as `"8.4"` resolves through a pinned table in
the project Dockerfile template.

## `access`

| Field | Type | Default | Notes |
|---|---|---|---|
| `apps` | `public` \| `private` | `public` | `public` brings [two enforced requirements](/security/public-sandboxes/). |
| `controls` | `password` | `password` | The only option. Not configurable away. |

## Substitutions

| Token | Available in | Expands to |
|---|---|---|
| `{name}` | `backends.*.build` | The service's `name` |
| `{out}` | `backends.*.build` | The path the built binary should be written to |
| `$SANDBOXR_MIGRATE_SINCE` | `database.migrate.command` | The value of `migrate.since` |
| `$SANDBOXR_D1_DIR` | `migrate.command`, `apps[].serve` | The sandbox's own database state directory. **Required** for `d1`/`sqlite`. |
