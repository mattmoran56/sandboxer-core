The easy case, and much cheaper to run. The file is `examples/workers.sandboxr.yaml` in the
sandboxr repo.

## The file

```yaml title="sandboxr.yaml"
project: worker-thing
sandboxr: ">=0.1.0"

database:
  driver: d1
  seed_from:
    # miniflare keeps its SQLite files here. `.wrangler/` is normally gitignored, so a
    # fresh worktree has no content — the tool snapshots from a checkout that does, and
    # falls back to migrating an empty database.
    file: .wrangler/state
    fixtures: seeds/fixtures.sql
  migrate:
    command: npx wrangler d1 migrations apply DB --local
  # Two processes opening the same D1 file deadlock, so exactly one service may own it.
  # This is a rule of the driver, not a workaround.
  owner: app

# No backends block at all. The worker IS the app.
frontends:
  apps:
    - label: app
      package: .
      serve: npx wrangler dev --port 8787 --ip 127.0.0.1
      port: 8787

secrets:
  read: [.dev.vars]
  keep: [API_TOKEN, SENTRY_DSN]
  never: ["DB_*", "*_URL"]

toolchain:
  node: "24.18"

access:
  apps: public
  controls: password
```

One hostname:

```
feat-123.app.worker-thing.sbx.lcl
```

## What to notice

### There is no backends block

The worker *is* the app. It is declared as a **server** front-end — `serve:` plus `port:` —
because `wrangler dev` is a long-running process, not a build that produces files.

This is exactly the case [the third runtime kind](/config/runtime-kinds/#server) exists for.
Without it you would have to lie: call it a backend and lose the app hostname, or call it
static and have nothing to serve.

Because it is a live dev server, it hot-reloads through the bind mount. Edit a file, refresh.
No `reload` command, no rebuild. That is the compensation for a server's idle memory cost —
and on a project this size, the cost is small enough that it is not marked `optional`.

### `package: .` means the repo root

A single-app project has no packages directory. `.` says "the repo root is the package", and
there is no `frontends.root` to prefix it with.

### The database is a file, so almost nothing is needed

Compare the `database` block here with [the MySQL one](/config/example-mysql-monorepo/):

| | MySQL | D1 |
|---|---|---|
| `version` | required — restore into the version production runs | absent; there is no server |
| Seeding | dump and restore | a file copy |
| Forking | dump and restore | a file copy |
| Version skew | a real hazard | does not exist |
| Advisory lock | required, so two migrations cannot collide | not needed |
| `owner` | not applicable | **required** |

[The driver model](/databases/drivers/) explains why the two are so different, and
[D1 and SQLite](/databases/d1-sqlite/) covers this driver specifically.

### `owner: app` is not optional

Two processes opening the same D1 or SQLite file deadlock. The config must name the single
service that owns the database, and here it is the only service there is.

This is not a workaround for a bug. It is a property of the file-based engine, and it is the
reason each sandbox gets a **private copy** of the file rather than sharing one.

<Aside type="danger" title="The symptom of getting this wrong is a hang, not an error">
Two writers do not produce a helpful message. Migrations hang, or fail with a busy error, and
whichever process you look at seems to be behaving correctly. If a D1 project hangs at
provisioning, count the processes that open the file before you look at anything else.
</Aside>

### `seed_from.file` points at a directory that is usually empty

`.wrangler/state` is where the local runtime keeps its SQLite files, and `.wrangler/` is
normally gitignored — so a *fresh* worktree has nothing there.

That is fine and expected. The seed is taken from a checkout that does have state, and with
nothing to seed from, the driver falls back to migrating an empty database. A project whose
migrations build the schema from nothing loses nothing at all.

### It is cheap

No database server, no object storage, no compile step, one process. A sandbox for this
project is a fraction of the monorepo's ~500 MB, and it starts in seconds because there is no
dump to restore.

If you are trying sandboxr for the first time and have a project like this, start here.
